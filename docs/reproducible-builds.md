# Reproducible Dependency Verification

TextLens commits both npm and Cargo lockfiles so automated verification and release builds can resolve the same dependency graph that was reviewed and tested.

## Frontend

For clean CI/release verification, use:

```bash
npm ci --no-audit --no-fund
```

`npm ci` must fail rather than rewriting `package-lock.json` when `package.json` and the lockfile disagree.

For ordinary local dependency changes, use npm normally, review the resulting `package-lock.json` diff, then rerun the clean verification path before merging.

## Rust

For CI/release verification, use locked Cargo commands where dependency resolution occurs:

```bash
cargo clippy --locked --all-targets --all-features -- -D warnings
cargo test --locked --all-targets
cargo run --locked --release --example benchmark -- 16 5
```

`cargo fmt --check` does not resolve dependencies and does not need `--locked`.

When intentionally changing Rust dependencies, regenerate `src-tauri/Cargo.lock` with Cargo, review the diff, then return to the locked verification commands.

## Lockfile policy

- Never hand-author either lockfile.
- Generate lockfiles only with npm/Cargo.
- Commit dependency manifest and lockfile changes together.
- Treat unexpected lockfile churn as reviewable dependency-supply-chain change, not formatting noise.
- Do not delete lockfiles merely to make an installation succeed.
- Release automation should consume committed lockfiles rather than floating to newly resolved transitive versions.

## Verified baseline

The first committed TextLens lockfiles were generated by the real npm and Cargo package managers in an isolated GitHub Actions branch workflow, validated as standard lockfile formats, and merged only after the temporary generator workflow was removed from the lasting pull-request diff.
